Android 原型验证架构设计：从 MVI 到 Kotlin Multiplatform

2026-06-10 Android 架构

在移动端架构演进中，MVI 模式通过单向数据流解决了状态管理的复杂度问题。本文结合实际项目经验，探讨如何将 MVI 与 Kotlin Multiplatform 结合，实现跨平台的状态逻辑复用。

核心架构设计

传统的 MVVM 在复杂页面中容易产生状态不一致的问题。MVI 通过 Intent → Reducer → State 的单向流，保证了状态的确定性。

MviViewModel.kt
class MviViewModel<S : UiState, E : UiEvent>(
    private val reducer: Reducer<S, E>
) : ViewModel() {

    private val _state = MutableStateFlow(reducer.initialState)
    val state: StateFlow<S> = _state.asStateFlow()

    fun dispatch(event: E) {
        _state.update { reducer.reduce(it, event) }
    }
}
Key insight: 将 Reducer 定义为纯函数，使得状态变更逻辑可以完全在 KMP shared module 中实现，iOS 端通过 K/N 互操作直接调用。

在 Kotlin Multiplatform 层面，我们将 Reducer、SideEffect、Repository 接口全部定义在 shared 模块中，平台层只负责 UI 渲染和平台特定实现……
